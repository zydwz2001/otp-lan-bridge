- Android：33 项 JVM 单元测试通过，`lintDebug`、`assembleDebug` 通过。
- Chrome 扩展：37 项测试通过，TypeScript 检查及生产打包通过。
- 检查 App 页面/资源、Android Manifest、扩展连接页 HTML/CSS：未改动。网页面板仅修改连接事件逻辑；Chrome manifest 仅改版本号。

新增测试覆盖 USB 无效地址配对、错误配对码拒绝、错误手机身份拒绝、Wi-Fi/USB 切换及拔线回退、等待状态保留、验证码重试去重、长度前缀帧，以及首次授权按钮的用户手势与一次性票据。

## 实机检查

使用 Windows 上的 Chromium 与已连接的 Xiaomi 15 Pro，覆盖安装 2.3.0 App并保留原配对。在独立测试浏览器中使用与该手机匹配的配对记录，设置无效 Wi-Fi 地址及端口 0：

- WebUSB 能直接打开手机 ADB 接口及固定本地 TCP 服务。
- 手机对不匹配的旧配对记录返回 `NOT_PAIRED`。
- 正确记录完成 HMAC 挑战及加密认证，状态显示在线，实际传输为 USB。
- 短暂关闭手机 Wi-Fi 后，USB 保持在线 45 秒，观察到两轮加密 PING/PONG；测试结束恢复手机 Wi-Fi 与本机 adb 服务。

测试使用独立的预授权浏览器配置和电脑已有的 ADB 身份；没有把自动化浏览器无法操作的首次设备选择弹窗算作实机通过。测试浏览器与日常 Chrome 同时使用相同配对记录时会替换彼此会话，因此独立保活测试关闭了手机 Wi-Fi，避免旧插件干扰。

## 尚需用户环境验收

- Chrome 首次设备选择与手机新 ADB 身份授权的完整交互。
- 受影响用户的校园网、不同电脑驱动、手机厂商及系统省电组合。

USB 数据通道已实机验证；上述系统授权及环境差异仍需在对应设备上确认。
