# Android App 使用方法

## 安装说明

App 的应用 ID 是 `io.github.zydwz2001.wifiotprelay`。首次安装需要开启通知使用权并完成浏览器配对；使用同一签名覆盖升级会保留原配对。

## 通知读取状态

- 前台必须显示“通知读取：已连接，可以接收短信”，真实短信验证码才能自动传递。
- 如果权限开关已经开启，但页面暂时显示“通知读取未连接”，App 会在后台自动重新连接：先请求普通重连，持续失败时在 Android 14 及以上回收旧连接并重新绑定。通常一分钟内恢复，不需要反复关闭、开启权限。
- 想立即处理时可点击“立即重新连接”。只有长时间仍未恢复，页面才会显示进入系统设置的入口。
- “发送测试验证码”只测试手机和浏览器之间的连接，不能证明系统通知读取已经连接。

## 首次设置

App 支持自动 USB 通信，不增加 Android 应用权限。使用 USB 时需要在系统开启 USB 调试、授权电脑，并在 Chrome 授权设备，见 [数据线连接使用方法](USB_CONNECTION.md)。USB 可用时无需正确的 Wi-Fi 地址及端口，但仍需原有通知读取、后台运行和配对授权。

2.3.3 在首页最下方增加“无 Wi-Fi 使用方法”。点击“开启 USB 调试”进入系统设置；若尚未启用开发者选项，会先提示连续点击版本号 7 次并提供“去关于手机”入口。返回 App 后，系统确认调试开关已开启才显示绿色 √。连上数据线后，在浏览器点击“连接手机”并选择手机即可继续配对。

1. 打开“验证码传递”。
2. 点“通知读取设置”，开启“验证码传递 · 通知读取”。
3. 点“防止后台断开”，允许 App 自启动。
4. 点“配对电脑”，按插件提示填写地址、端口和配对码。
5. 浏览器询问访问本地网络时，点“允许”。
6. 配对成功后选择短信应用，再点“开始传递”。

首页按“系统设置 → 配对电脑 → 开始传递”从上向下排列。设置成功后，“通知读取设置”和“防止后台断开”会显示完成图标；配对成功后，“配对电脑”会变为灰色“取消配对”。

## 后台运行

开始传递后，Android 会自动显示一个低优先级常驻通知，用于维持手机与浏览器的连接；可直接退出 App 或锁屏，不需要让页面一直显示。Chrome 插件每 20 秒与手机交换一次心跳，短暂断线后会自动重连。

如果关机前处于“正在传递”，本版本会在手机重启或 App 更新后尝试恢复服务。小米 / Redmi / POCO 的澎湃 OS 默认可能禁止应用自启动：点击 App 第一屏的“防止后台断开”，按提示找到“验证码传递”并允许自启动，设置一次即可。如果常驻通知仍会消失，再把 App 的省电策略设为“不限制”。这些属于系统厂商限制，不要求日常把 App 留在前台。

## 测试

浏览器进入等待状态后，点击 App 的“发送测试验证码（可选）”。若浏览器能收到测试码，说明当前连接、配对、加密协议和网页面板链路正常；真实短信仍失败时，应重点检查短信 App 包名和锁屏通知内容。等待会话建立时，App 会在通知读取重连窗口内多次回查刚到的系统通知，避免短信先于等待指令到达而漏码。

Android 2.2.6 将回查延长到整个等待期间：每秒检查一次所选短信 App 的近期通知，弥补系统通知回调延迟或遗漏。等待期间临时保持 CPU 唤醒，不点亮屏幕；取消、断线、监听断开或等待到期后释放。同一条验证码在本次等待中只发送一次，浏览器未确认时仍沿用原来的消息重试。系统尚未提供通知正文时，回查仍无法读取其中的验证码。
