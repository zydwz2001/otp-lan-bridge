# 数据线连接使用方法

没有 Wi-Fi，或校园网不允许手机与电脑互访时，可以用数据线连接。USB 可用时自动优先使用；原来的短信读取、等待、确认填写及登录操作不变。

2.3.3 在 App 最下方增加“无 Wi-Fi 使用方法”，提供设置路径和跳转按钮。只有系统确认 USB 调试已开启才显示绿色 √；该勾号表示调试开关已开启，连接是否成功仍以原来的在线状态为准。插件设置底部提供一行灰色提示，点击后展开步骤。

## 首次使用

1. 覆盖安装 2.3.3 App，覆盖原扩展目录并在 Chrome 刷新扩展、刷新网页。已有配对可以保留。
2. 在 App 最下方点击“开启 USB 调试”，进入系统开发者选项并开启“USB 调试”；返回 App 后显示绿色 √。使用支持数据传输的线连接电脑与 Android 手机，按系统提示授权此电脑；无需开启无线调试。
3. 未配对时，在 App 点“配对电脑”，输入原来的 6 位配对码并点击网页“配对手机”。已经配对时，点原来的“重新连接”。
4. 在原有连接窗口点击“连接手机”，Chrome 会显示设备选择器，选择这部手机。若手机再次弹出调试授权，核对电脑并允许。浏览器的 ADB 身份与命令行 adb 可以不同，因此以前授权过 adb 仍可能需要再次确认。
5. USB 可用后，地址和端口可以留空、保留旧值或填写错误值；插件通过固定的手机本地服务连接。正确配对码仍然必需。App 仍要开启通知读取并运行传递服务。

Chrome 插件请使用 2.3.2 或更新版本。首次连接页在带工具栏的普通 Chrome 窗口中打开，页内内容与按钮保持原样。2.3.0–2.3.1 使用的无工具栏弹窗会使部分 Chrome 版本无法显示设备选择器，继而误入 Wi-Fi 流程；2.3.2 已修正。授权成功只关闭连接页，不会关闭用户在该窗口另开的标签页。

这些是 Android 和 Chrome 的系统授权，不能通过隐藏产品界面省略。后续在同一扩展身份、同一浏览器配置下，通常会自动使用已授权设备；用户撤销授权、清除数据或更换扩展身份后需再次授权。

不用 USB 时，在设备选择器取消，继续原有 Wi-Fi 授权及连接流程。没有可用 USB 且地址无效时仍会报错，不会把未建立的链路显示为在线。

USB 调试常见路径：**设置 → 系统 / 更多设置 → 开发者选项 → USB 调试**。找不到开发者选项时，先进入“关于手机”，连续点击“版本号”7 次（部分手机先进入“软件信息”；小米可在“全部参数与信息”中点击“OS 版本”或“MIUI 版本”）。App 底部按钮会先引导打开“关于手机”，完成后返回 App 再点一次按钮。

## 自动切换

- 启动、重连或检测到设备连接时，先检查已获 Chrome 授权的 USB 设备。
- 已配对时，必须验证手机的配对密钥证明，验证通过才从 Wi-Fi 切到 USB；不会仅凭设备名称或序列号接受另一部手机。
- USB 在线期间，Wi-Fi 地址变化不会停止 USB 服务。插件只接受认证后的真实 Wi-Fi 地址，供后续回退使用。
- 拔线后尝试 Wi-Fi；若校园网不允许互访，会显示离线并等待恢复。未结束的等待请求会在恢复后继续，不重新开始 5 分钟计时；验证码按原消息标识重试和去重。
- 系统休眠、撤销调试授权、线材断开、App 服务停止等仍会导致离线，不能保证任何情况下永远在线。

## 技术与限制

浏览器使用 WebUSB 和 Tango ADB 库，直接打开手机 `tcp:42872`。App 仅在 `127.0.0.1:42872` 监听该服务，Wi-Fi 的 WebSocket 地址和端口保持独立。USB 传输采用长度前缀帧，与 Wi-Fi 共用原 ECDH 配对、HMAC 认证、AES-GCM 消息、心跳、等待及投递逻辑。无需安装电脑辅助程序或运行端口转发命令。

这条链路不经过校园网内部路由，因此可以避开 AP 隔离造成的手机与电脑互访失败；它不会修复校园网本身，也不替代网页联网。Android 通知正文被系统隐藏、短信 App 未发通知等问题仍需分别处理。

USB 调试接口可能被 Android Studio、adb、投屏软件或另一浏览器独占；插件不会结束这些程序。Windows 需要正常可用的 ADB 驱动，部分受管电脑或手机可能禁用调试/WebUSB。现阶段以 Windows + Chrome + Android 为主要验证环境，其他系统和厂商组合需实机验证。

Android Manifest 与 Chrome 原有 manifest 权限列表保持不变；新增的是浏览器设备授权和系统调试授权。调试授权范围比验证码业务更广，只应授权信任的电脑。产品仅调用固定 TCP 服务，未提供 shell、文件操作或任意转发功能。

## 验收范围

自动测试覆盖：无 Wi-Fi 地址配对、错误配对码拒绝、另一手机身份拒绝、USB 优先和拔线回退、等待请求保留、未确认验证码重试去重、帧分片及长度限制，以及权限窗口的点击时机和票据限制。

发布前实机应检查：首次 Chrome 选择器与手机调试授权；校园网/移动数据环境；锁屏和长时间空闲；拔插与浏览器重启；真实短信接收。自动化测试不能替代所有系统授权、驱动和省电策略组合。
