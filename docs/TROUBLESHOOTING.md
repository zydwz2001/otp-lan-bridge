# 故障排查

按以下顺序检查，通常能快速定位问题。

## 更新插件后出现 Extension context invalidated

这个错误表示当前网页的扩展脚本已经失效，常见于刚刷新、更新或重新启用插件后；旧面板上残留的“手机在线”不能证明当前连接正常。

先在 `chrome://extensions` 刷新扩展，再回到报错网页按 `Ctrl+Shift+R`；加载新脚本后再点“展开设置”。不需要解除手机配对。Chrome 2.3.1 会在检测到失效后取消旧在线显示、停用旧操作，并明确提示刷新当前网页。仍停留在旧脚本中的页面需要刷新一次才能获得修复。

## 1. 手机没有显示 Wi‑Fi 地址

以下地址检查仅针对 Wi-Fi。2.3.0 的 USB 链路不依赖 Wi-Fi 地址，步骤见 [自动连接说明](USB_CONNECTION.md)。

- 确认手机连接的是 Wi‑Fi，不是只有移动数据。
- 点击“停止传递”，然后重新点击“开始传递”。
- 地址必须属于 `10.x.x.x`、`172.16–31.x.x` 或 `192.168.x.x`。

## 2. 配对超时或无法连接

- 对照 App 当前状态逐字符检查 IP 和端口。
- 手机 App 保持前台，刷新配对码后重试。
- Chrome 142+ 的本地网络权限提示必须选择允许。
- 没有出现提示时，先看连接窗口是否已经继续：Chrome 记住“允许”后不会重复弹窗。
- 连接窗口长时间没有结果时，在手机 App 中点击“停止传递”，再点击“开始传递”，然后回到网页重新配对。
- 如果错误页仍显示登录网站尝试连接 `ws://手机地址` 的 `Mixed Content`，说明 Chrome 还在运行旧脚本；到 `chrome://extensions` 点击插件卡片的刷新按钮，再刷新登录网页。
- Windows 防火墙一般不会阻止电脑主动连接手机；公司安全软件可能阻止私有网段 WebSocket。
- 路由器开启 AP/客户端隔离时，两台设备无法通过该 Wi-Fi 直接访问。可以换可互访网络，或使用 2.3.0 的 USB 链路。

使用数据线仍离线时：确认两端都已更新、线材支持数据、USB 调试已开启、手机已允许此电脑、Chrome 已选择设备且 App 服务正在运行。若 Android Studio、adb、投屏或其他浏览器正在占用同一 USB 调试接口，先结束占用；插件不会强行终止其他程序。Windows 上还应确认手机的 ADB 驱动正常。

若点“连接手机”后完全没有设备选择器、直接显示等待本地网络连接，请将插件更新到 2.3.2。旧版的无工具栏弹窗无法承载 Chrome 的扩展设备选择器，新版改用普通 Chrome 窗口，页面内容不变。更新后关闭旧连接窗口，刷新扩展和原网页，再重新连接。

## 3. 配对成功但显示手机离线

- App 的常驻通知应存在，状态应显示“正在传递”。
- 2.2.5 及以上版本会在旧地址失败后自动寻找已配对手机，并保存手机通过加密状态消息返回的新地址。请确认手机 App 和 Chrome 插件都已更新；如果所在网络屏蔽 mDNS 或启用了客户端隔离，再在插件展开设置中手动更新地址并点击“保存新地址并重连”。地址已经保存但仍显示离线时，点击同一位置的“重新连接”，无需解除配对。
- 电脑或 Chrome 冷启动后会自动重连；持久化闹钟最迟会再次唤醒后台尝试，打开网页、切换标签或重新聚焦浏览器也会立即补连。VPN 不负责这条局域网连接。
- Android 省电策略可能停止前台服务；为 App 允许后台运行。

## 4. 测试码成功，真实短信失败

- 如果下拉通知栏后验证码才传来：2.2.5 及以前只在开始等待后的 0、0.75、2 秒回查通知，之后完全依赖系统回调。Android 2.2.6 在整个等待期间每秒回查，并临时保持 CPU 唤醒，防止只能等待通知栏刷新或手机唤醒才继续处理。覆盖安装 APK 即可，原配对保留。
- 先查看 App 前台是否明确显示“通知读取：已连接，可以接收短信”。如果显示“未连接”，点击顶部“立即修复通知读取”，在系统页面关闭后重新开启该权限。
- App 选择的短信包名必须等于最近真实通知来源。
- 通知预览必须显示正文数字；“隐藏敏感通知内容”会让 App 无法解析。
- 建议先在网页点击“一键填充并等待”，再请求短信；如果短信与等待指令几乎同时到达，新版 App 会自动回查近期通知。
- 银行、支付、钱包、转账或交易通知会按安全策略被主动拦截。

开发排查可运行 `adb shell dumpsys activity service io.github.zydwz2001.wifiotprelay/.OtpNotificationListener`。`snapshotReads` 应在等待期间持续增加，`captureWakeLockHeld` 应在等待结束后变为 `false`；`smsCallbacks` 只统计系统实际回调，不把回查算作回调。这些诊断仅包含计数、时间和状态，不输出验证码或短信正文。

若回查正常但通知没有正文，应继续检查系统的内容隐藏设置。[Android 通知监听 API](https://developer.android.com/reference/android/service/notification/NotificationListenerService) 只能返回系统提供给监听器的通知；[Android 15 的敏感通知保护](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction) 也可能隐去验证码。持续回查不会绕过这些限制。

## 5. 点击填写没有反应

- 先点击正确的网页输入框，让扩展记录目标。
- `chrome://` 页面、Chrome 商店和其他受保护页面不允许内容脚本运行。
- 检查网站是否被加入插件的排除域名列表。
- 分格验证码输入框要求候选码长度与格子数量一致。
