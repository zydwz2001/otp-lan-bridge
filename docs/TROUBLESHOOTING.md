# 故障排查

按以下顺序检查，通常能快速定位问题。

## 1. 手机没有显示 Wi‑Fi 地址

- 确认手机连接的是 Wi‑Fi，不是只有移动数据。
- 点击“停止传递”，然后重新点击“开始传递”。
- 地址必须属于 `10.x.x.x`、`172.16–31.x.x` 或 `192.168.x.x`。

## 2. 配对超时或无法连接

- 对照 App 当前状态逐字符检查 IP 和端口。
- 手机 App 保持前台，刷新配对码后重试。
- Chrome 142+ 的本地网络权限提示必须选择允许。
- 没有出现提示时，先看连接窗口是否已经继续：Chrome 记住“允许”后不会重复弹窗。
- 连接窗口长时间没有结果时，在手机 App 中点击“停止传递”，再点击“开始传递”，然后回到网页重新配对。
- 如果错误页仍显示登录网站尝试连接 `ws://手机地址` 的 `Mixed Content`，说明 Chrome 还在运行旧脚本；到 `chrome://extensions` 点击插件卡片的刷新按钮，再刷新登录网页。
- Windows 防火墙一般不会阻止电脑主动连接手机；公司安全软件可能阻止私有网段 WebSocket。
- 路由器开启 AP/客户端隔离时，两台设备无法直接访问。请换普通家庭 Wi‑Fi，本项目不会绕过隔离。

## 3. 配对成功但显示手机离线

- App 的常驻通知应存在，状态应显示“正在传递”。
- 手机 Wi‑Fi 地址变化后，在插件展开设置中更新地址；只有内容发生变化时才会出现“保存新地址并重连”按钮，点击后保存并重新连接。
- Android 省电策略可能停止前台服务；为 App 允许后台运行。

## 4. 测试码成功，真实短信失败

- 先查看 App 前台是否明确显示“通知读取：已连接，可以接收短信”。如果显示“未连接”，点击顶部“立即修复通知读取”，在系统页面关闭后重新开启该权限。
- App 选择的短信包名必须等于最近真实通知来源。
- 通知预览必须显示正文数字；“隐藏敏感通知内容”会让 App 无法解析。
- 先在网页点击“一键填充并等待”，再请求短信。
- 银行、支付、钱包、转账或交易通知会按安全策略被主动拦截。

## 5. 点击填写没有反应

- 先点击正确的网页输入框，让扩展记录目标。
- `chrome://` 页面、Chrome 商店和其他受保护页面不允许内容脚本运行。
- 检查网站是否被加入插件的排除域名列表。
- 分格验证码输入框要求候选码长度与格子数量一致。
